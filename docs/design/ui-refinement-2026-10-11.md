## 布局规格

- HUD：身份签牌缩窄，细边替代粗黑框，点数只显示数值并保留完整提示。窄窗口和大字号时相册、拍照、设置采用具名图标，宽窗口恢复文字；桌面模式仍只有右键菜单。
- 货架：等比图像、名称、最多两行描述、价格或拥有状态、主操作四层结构。描述完整内容保留在提示中。八件头脸饰品直接使用真实猪 rig 试戴，不单独堆砌配饰缩略图。
- 已佩戴：绿边卡片与选中按钮，不可重复购买。零食每次投喂仍收费，不能用“拥有”推断免费。购买、佩戴和摘下保留滚动位置，切家具分类归顶。
- 网格：由面板真实宽度、主题边距、滚动条余量、字号和最小卡宽计算列数；1280×720/150% 下货架仍可两列，不机械强制单列。
- 大字号卡片将等比图像与文案横排，价格与操作保持全宽，避免第一行商品的购买按钮被巨大的空白图像区推到屏幕外。动作按钮缩短为“展示动作”，整数点数不显示多余小数。
- 相册：保留五页、页序、键盘焦点、未读标记与 GameSession 拆信事务。每页用不传播固有最小尺寸的 Control 包裹，页面内部独立滚动；外层关闭重复滚动，打开其他面板恢复自动滚动。日记也有自己的滚动容器。
- 色板与字体不变：`#FFFDF7`、`#2B3030`、`#EF7390`、`#60765B`、`#E6E4D9`；霞鹜文楷标题、Noto Sans SC 正文。新增本地化文案由现有生成器与离线字体子集工具产生。

## sly 嘴部策略

跪姿和趴姿的稳定帧原本就禁止独立嘴。检查发现动态绘制仅依据权重中点切换的 selected 姿势判断显隐，因而切入低姿势的前半段和起身的后半段仍可能显示站姿嘴。

现在任何过渡只要源或目标姿势、表情不允许嘴，整段都不画嘴；完全回到安全站姿后恢复。绘制与显隐共用原 rig 的脸部安全区和等比变换，不修改原脸稿、眼睛、身体或家具锚点。

回归增加 sly 的站立↔跪下、站立↔趴下，两个朝向、贴地/非贴地、0/10/35/49/50/51/65/90/100% 相位与排队动作；保留全部稳定身体/表情组合和其他表情的动态检查。

## 核验范围

本轮证据位于 `build/validation/ui-refinement-20261011/`。基线嘴专项 5091 项中 192 项失败，证明旧显隐规则不满足整段过渡隐藏要求；`before-mouth` 是审计脚本缩进错误的中止记录，不能当有效基线。首轮 UI 150 张截图发现拆信刷新仍把新包装页当作 ScrollContainer、其他面板未恢复滚动，这两个回归均修正。

最终有效渲染证据在 `accepted`：UI 3390 项/150 PNG、嘴部 5091 项/35 PNG 均通过，共 185 张实际 Godot 截图，三语/720p/16:10/超宽/80%/150% 和最小窗口额外覆盖。大字号第一行饰品操作无需滚动即可看到；购买/已拥有重戴/摘下、付费投喂、点数到账即时可用、分类归顶、五页导航/焦点、拆信刷新与持久化读状态均核验。嘴部逐相位测试强制重绘后再读取纹理，避免把生产低频绘制保留的上一帧与下一相位比较；生产动作节流未改变。

Python 172 项与内容校验通过。导出证明和核心/节奏检查以 `headless-accepted.log`、`packages` 下的实际结果为准。仅验证本轮 HUD、货架、相册及相邻设置布局，不把旧桌面侧栏/气泡审计当作验收，也不恢复用户已经删除的控件。Windows 原生、长期运行与最终素材门禁保持独立。
