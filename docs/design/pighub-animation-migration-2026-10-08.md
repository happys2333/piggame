# 同主体黑眼动态素材迁移

## 设计与接入

保留用户选择的桃粉豆形主体、U形耳、短圆腿、卷尾和粉鼻子。内置 image_gen 新生成两张动作原稿与一张透明五官原稿，复用已选定的八表情原稿；不使用第九张白眼球表情。永久 `face_quake` ID 仅别名到黑眼惊讶，兼容既有内容引用，不新增一套图。

12种身体循环、每种4帧：站立迈步、趴下呼吸、躺平压扁、抱头、跪下、缩成一团、张开前腿、四脚朝天、探头、低姿爬行、打工敲键盘、纸冠披风挥手。36个模拟行为共用这些循环，以已有家具道具和8套黑眼五官组合；不是36套重新设计的角色。普通猪、小剧场、独立住客、照片与生活计划缩略图共用 `PigVisualRig`，不再走旧整角色切换。48个收藏ID/解锁与名称保留，复用8套基础表情。

每一帧从真实鼻孔测量鼻部中心，眼在鼻上方，趴下、躺平、缩团护脸、低姿爬行和打工五种姿势直接隐藏嘴，不在手上补嘴；其他姿势的可见嘴紧邻鼻子正下方居中，取消横向偏移。绘制和鼻子点击共用同一帧锚点。两张图集实际都不是等高行，使用透明间隙中的显式行边界，避免切掉头、尾和脚，也不带入相邻行的猪；第一张边界为 `[0,283,504,699,977,1238,1536]`，第二张为 `[0,235,442,651,834,1017,1224]`。附件按鼻部和耳顶落位，不再复用旧贴纸猪坐标。

PNG原字节不改写，不做程序重绘/抠图；裁区、透明噪点外缘收边、五官和附件落位均是Godot运行元数据。当前姿势显隐修正版真实白底预览在 `build/validation/art-review-mouth-hidden/`，此前居中尝试在 `art-review-mouth-fixed/`，旧 `art-review/` 保留为修复前证据，用游戏绘制路径而非RGBA原图查看器判断视觉。

## 清理与优化

移除12张已替代运行PNG：`behavior_01`至`behavior_06`、`expressions_01/02`、`performance_body_01/02`、`performance_faces`，以及仍残留旧猪脸的`status_icons`；应用图标也用内置image_gen换成同主体黑眼版本。删除12张素材共18,591,176字节；新增4张共享图集并替换1张应用图标，状态图标直接复用八表情源，不另复制图集；全体运行PNG由26张/35,580,577字节降为18张/20,939,005字节，净减少14,641,572字节（41.15%）。没有删除用户参考图、来源提示词、许可、存档或玩家照片；不手改`.godot`与`.import`。

构建来源同步移到 `superseded_records`，总构建器删除旧身体/表情配方代码，不会把删掉的图片再复制回来。生成记录保留完整提示词和原字节哈希；新增图片来自用户授权的主体参考，不宣称为用户专属原创或已获发行权属验收。

清理旧程序猪、五官/道具和附件绘制分支，统一骨架；预计算脸部矩形，装扮动作按ID索引而非每次复制/遍历12条；相同源/裁区的别名共用纹理包装，LRU仍上限8图集，连续访问同图集不反复调整LRU。隐藏节点/减少动态不推进动画；慢动作2.5FPS、一般5FPS、迈步10FPS，模拟与收益不受影响。

## 重建与验收

先运行 `python3 tools/build_pighub_rig.py`，再运行 `python3 tools/build_generated_visuals.py --copy` 并将输出作为视觉清单。两者只测量/复制原图，不生成位图。`pig_visual_rig.json`纯表现配置，不含收益、需求、冷却或存档字段。

完整实现后集中验证一次；失败只针对对应项目复查。真实Windows透明/穿透、拖动/触控/DPI、游戏前台和资源权属仍独立待验收；音频继续静音开发占位，最终资源门禁不解除。

收尾实际主窗口与单猪截图发现第一张图集的等高裁区仍切头尾、混入下一行；此前动作白底预览早于最终元数据，不作为当前裁区通过证据。检查确认第一张24帧中20帧的裁区边缘含显著不透明像素。只更新裁区并重算同帧五官/鼻部锚点，不重绘PNG或改变模拟；新增测试逐一检查全部48个实体帧的四条边均不切到不透明素材。后续仅复查受影响的素材、UI、四帧与导出，不重复完整核心/节奏流程。

## 11:43反馈后的嘴部修正

用户截图中的趴下/躺平歪嘴来自构建器的侧嘴分支：六种姿势横移0.9个鼻宽。现全部姿势以每帧鼻下居中为统一规则，仅改24个嘴锚点，不改变主体、眼睛、裁区、鼻部命中或18张PNG原字节。新增测试使用嘴图层原始黑色像素中心及真实渲染缩放/偏移检查384种组合，旧数据稳定失败192项，修复后16项相关回归通过；实际Godot重绘48帧与八套五官并查看两页修正版。两包/EXE串行重建并加载通过，不重复核心/节奏/完整UI/性能全流程。旧UI缓存和性能JSON保持历史身份，不能绑定新嘴锚点；最新范围见 `build/validation/pighub-mouth-scope.json`，候选身份以候选清单为准。

## 嘴部显隐补充

用户进一步指出鼻下居中仍会落在护脸的手上，因此不再强行给全部姿势补嘴。构建器为12个身体配置 `mouth_visible`：趴下/躺平/缩团护脸/爬行/打工为false，其余true；共享渲染器跳过隐藏嘴的纹理请求与绘制，所有黑眼表情遵守同一姿势规则，不改变眼鼻位置、PNG原字节、互动或模拟。Python17项和真实Godot384组合检查通过；160隐藏组合只保留身体与两眼，224可见组合另保留嘴。原渲染器在有隐藏数据时仍画嘴的负基线已复现，修复后两页48帧实际预览已查看。两包/EXE串行重建并加载，不重复完整测试流程。证据与当前范围为 `build/validation/pighub-mouth-hide-*`；此前仅检查居中位置不代表遮挡处理正确。
