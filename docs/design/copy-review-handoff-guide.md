# 猪咪游戏：交给另一位AI的文案优化包

## 先读这些

这是现有文字的只读快照，不是已优化版本。共有 {{LOCALIZATION_COUNT}} 个本地化键，涵盖简体中文、繁体中文和英文；包括当前使用文案，以及仍留在翻译表、但未发现直接引用的条目。后者可能通过动态键选用，也可能是兼容遗留，**不能因此删除或重新增加对应功能**。

当前游戏不会因为这份整理包改变任何文案、数值、存档或美术。请优先优化简体中文；繁体/英文可以一并优化，也可以保持原样留待之后处理。现有繁体主要由OpenCC转换得到，不应冒称已逐条人工本地化。

## 文件怎么用

- `all-text-readable.md`：按19个模块逐条阅读，三种语言的当前原文、用途、变量、约束与源文案位置全部保留。
- `zh-CN-only.md`：只看简体中文的轻量全集，适合先交给中文编辑AI；仍保留key和变量。
- `all-text-editable.csv`：主要回填文件。只填写 `zh_CN_optimized` / `zh_TW_optimized` / `en_optimized` 和 `edit_note`；其余列保留原样。空白优化列表示“不改”，不表示删除文字。UTF-8 BOM便于Excel打开；段落原文保留CSV引号内换行。
- `all-text.json`：适合AI处理的同一份全集；在 `proposed` 中写建议，`null` 表示不改。数据引用带内容ID、对应字段及等级/价格/事件等背景；代码引用是静态引用位置，不是运行时可见性的证明。
- `return-template.json`：也可以只返回需要改的键，格式见下面例子，不必重发完整846条。
- `project-metadata.json`：游戏名与窗口描述两个配置项；它们不是本地化键，单独提交建议，不要混入主表。
- `embedded-image-text.md/json`、`reference-images/`：八张PigHub明信片原图及人工可辨文字记录。图中烧录文字不是翻译表文案；图内细字/水印不确定之处明确标注。可以提修改建议，但不要声称改CSV即可改变图片，也不要抹掉来源信息。
- `originals/game.csv`：字节不变的源翻译表，作为对照，不直接编辑。
- `originals/steam-store-copy.md`：对外商店文字附录。它还包含发行交付说明，**不是全部都出现在游戏里**；标题、数量和真实承诺必须一致，不把待交付内容写成已支持。
- `originals/privacy.md` / `third-party-notices.md` / `SOURCE.md`：隐私与素材来源事实，不能凭文案优化修改权利/许可结论、宣称原创或已获发行批准。
- `originals/support-and-known-issues.md`：支持文案与已知问题附录，含历史描述和发布模板，不是新增玩法需求。
- `manifest.json`：基线与文件哈希、条目数量和变量清单，供回填核对。
- `placeholder-guide.json`：全部实际花括号变量的通用释义，具体含义以每条上下文为准。

## 优化方向

请作为中文游戏文案编辑，优化一个离线、单机、轻量放置桌宠游戏。主角是黑眼珠、简单夸张、有点丑萌的粉色猪咪，参考PigHub那种认真胡说的梗感，而不是说教、卖惨或过度幼儿化。它是陪伴，不是需要打卡的任务。

1. UI操作清楚、短、统一；标题、正文、提示各司其职，不把按钮写成解释段落。考虑1280×720及150%字号，避免靠长句占满界面。长度目标只是设计建议，不应为了统一字符数损失意思。
2. 台词自然、有生活感，可以有猪相关谐音梗，但别每句硬塞同一类梗。小剧场的随机对白保持版本间差异；用短而准的落点，不复述画面上已经明显看见的每一步。
3. 活泼、傲娇、懒惰、社恐、贪吃有各自声线；傲娇不恶毒，社恐不被羞辱，贪吃不催逼玩家。注意睡眠、休息、陪伴相关表达不制造内疚。
4. 表情名、事件名、解锁提示、成就条件和手账引用要联动。一处改名时列出相关键；`EXPR_*_HINT` 目前由关联事件标题生成，不能只改导出CSV而忽略生成规则。
5. 英文可重新表达笑点，不需要生硬直译汉字谐音；繁体保持自然用词。不要把“猪咪/猪猪”任意替换成猫或其他主体。“熟悉度”“日常点数”“小剧场”“桌面陪伴”的UI术语应统一。
6. 不新增提示气泡、桌面边栏、每日签到、通知催促、错过惩罚或推销段落。不通过文案虚构新的玩法。

## 不可改变的事实

- 单机、一次买断、离线优先；没有账号、广告、内购、签到连续奖励、付费加速或不可补得的限时内容。
- 猪不会死亡、离家、掉熟悉度，或因玩家离开而责怪玩家；不能用“再不喂就……”一类恐吓。
- 活动可穿戴目录只有8件头部/脸部饰品，不恢复围巾、领结、披风、裤子、裙子等入口。现有特殊形态的名称可以调整，但不能靠改名新增系统。
- 现有内容为36种行为、32件家具、10种零食、8件饰品、48个收藏表情、24段小剧场/60个对白版本、24个成就、8张永久明信片、6个小计划/18段手账。
- 点数价格、等级/进度解锁、奖励、冷却、Demo范围与时间等属于现有玩法，文本不能随意改数字。零食每次投喂收费，已拥有饰品重复佩戴不再次收费。
- 防打扰依据本游戏焦点，不扫描其他进程/窗口，不监听全局键鼠，不录制系统音频，不抓取玩家桌面。截图相关文字不能说成已支持“与当前桌面合影”。专注计时25/5，只在内存中，不保存工作历史。
- 置顶受严格防打扰限制；不把“置顶开关”写成“永远覆盖其他游戏”。桌面没有边栏或来信气泡，以右键菜单操作；保留普通小窗降级。
- 音频仍是强制静音的开发占位，Windows原生兼容性与最终素材仍待独立验证。不可承诺已验证所有系统或已经有可听的配乐。
- 存档错误、重试、保护原文件、备份路径等安全信息不能删成一句“出错啦”。隐私与素材来源声明只能增强可读性，不能改变事实或隐去重要限制。

## 回填协议

**不要改key、内容ID、原文列、源引用、哈希、变量名或变量数量。不要删除条目、调换含义或改程序结构。**

- `{name}` 是自定义猪名，不是可替换成“猪猪”的固定占位；`{price}`、`{path}`、`{level}` 等同理。每条 `variables` 列给出需要原样保留的花括号标记，三语应一致。可以调整它们在句中的位置。
- 保持重要段落换行、百分比/时间单位、格式化文本含义；有疑问列入 `questions`，不要猜。
- 优化列空白、JSON `null` 或未列入 `changes` 都意味着保留当前版本。若确实建议删除一个显示场景，请单独说明理由，不能以空字符串偷偷删除。
- 标题/摘要/提示有耦合关系时，在 `edit_note` 说明需要同步的键；不要新增CSV里不存在的键。
- 回填时会修改源生成器与对应规则，再重建三语CSV/字体并检查长度；**只修改 `game.csv` 会被 `tools/build_localization.py` 重生成覆盖**。本次不执行回填。

推荐返回以下JSON结构，也可以返回填写好优化列的CSV：

```json
{
  "schema_version": 1,
  "localization_csv_sha256": "复制return-template.json中的实际哈希",
  "changes": [
    {
      "key": "从原表复制真实key",
      "original_text_sha256": "复制该条原文哈希",
      "zh_CN": "保留所有变量的建议简体文本",
      "zh_TW": null,
      "en": null,
      "reason": "简述修改理由和相关联动键"
    }
  ],
  "metadata_changes": [],
  "image_caption_suggestions": [],
  "questions": []
}
```

游戏标题/描述的建议用 `metadata_changes`，注明 `PROJECT_CONFIG_NAME` 或 `PROJECT_CONFIG_DESCRIPTION`；它们不是实际本地化键。图内文字建议用 `image_caption_suggestions`，注明明信片ID；本轮原图保留不动。商店/隐私/支持附录的修改另交Markdown，并明确文件名与段落，不混进本地化 `changes`。
