# 自定义起名与多猪养成

2026-10-07 用户要求自定义名字和复数养成。第一版支持最多四个永久住客 ID，每只独立养成，切换当前小屋/桌面陪伴，不同时创建多份桌宠窗口。用户未指定共享房间或同屏多猪，本轮采用低打扰的独立档案方案；同屏互动不属于本轮完成范围。

## 玩家操作

- 每只另有独立性格，首次欢迎/接纳可随机或自选；旧档可补选一次，改名与切换不改变它。五种互动表情与口吻均无经济属性差异，详见 `docs/design/personalities.md`。

- 设置中的“猪猪住客 · 起名与陪伴”提供当前猪猪改名、新住客起名和切换。首次命名保留原有引导，之后改名不重置引导或进度。
- 名字支持中文、繁体、英文和 emoji，去除首尾空格，最多 16 个 Unicode 字符；拒绝空名、内嵌换行/控制字符和过长输入。重复显示名可用，住客编号和永久 ID 区分身份。
- 新住客从自己的第一天开始，拥有独立熟悉度、状态、点数、小屋家具、装扮、表情、事件/照片、小计划与手账。没有共用点数、转账、登录要求或弃养/死亡按钮。
- 其他猪猪按现有离线规则生活：在切换回来时懒结算认可的至多 24 小时间隔，不播放错过的动画，不因少看一只而倒退。反复切换同一时刻不会重复获益。
- 桌面只显示当前一只；先从右键菜单返回小屋再管理住客，避免切到尚未解锁桌面模式的新猪后失去可达控件。

## 保存与兼容

- 保持 schema 4。未使用多猪功能的旧档仍采用原顶层字段，第一只沿用 `pig_1` 和原相册路径，机器本地窗口设置不进入住客进度。
- 启用后增加 `active_companion_id` 与 `companions`。每只包含猪咪状态、两个导演、当前模拟和独立时间锚；顶层镜像必须与当前住客一致。同一原子文件和两份轮换备份保护整个住客组，不制造分文件切换的部分提交。
- 所有住客（含非当前）均执行既有内容/类型/范围验证。拒绝未知 ID、缺少第一只、嵌套/额外快照章节、镜像不一致、非当前猪的非法进度或跨猪照片路径；坏主档恢复有效整组备份。
- 新住客照片和手动截图放入 `companions/<永久 ID>/`，避免相同事件 ID 覆盖第一只。Demo→正式版导入保持全部住客及各自的相册路径转换，Demo 的目录范围不变。
- 改名、接纳和切换保存失败时不显示成功，不更换当前身份，不丢失原有快照。睡眠恢复后的立即切换会先把离开的猪咪补上认可时间，再在同一事务提交目标猪。
- 本地各猪成就独立；平台成就合并已有解锁，统计取住客的最高值，避免切到新猪后降低已有平台进度。平台仍无实际凭据，本机验证不等于 Steam 上线验收。

## 验收范围

核心回归覆盖 Unicode/边界名字、四只独立进度、照片隔离、时间锚、防切换刷点、唤醒立即切换、失败回滚、坏字段和整组备份恢复；真实 UI 回归使用设置、起名、接纳和切换按钮，并检查三语与 80%/150% 最小窗口布局。Windows 原生输入、文件系统/云同步、平台及体验仍待外部验收。
