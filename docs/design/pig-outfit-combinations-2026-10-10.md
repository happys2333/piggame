# 猪咪装扮与状态联合校验

本文件记录下架前的十二件配饰修复和当时证据。随后用户要求仅保留头脸饰品，当前八件目录、旧档退款与新预览见 `head-face-accessories-2026-10-10.md`；以下十二件矩阵和包身份不代表当前范围。

## 问题与修复

用户截图中的云朵围巾采用固定 55 单位宽度和鼻子下方硬偏移，在不同体型中像贴在前腿上的小徽章；趴卧时还被地面钳制向脸部推。帽子、发带和圆眼镜的旧图另带有猪耳，叠加后会多出身体部件，星形眼镜的旧镜片也会盖住黑色眼珠。

- 仅通过内置 image_gen 编辑配饰图集，去掉配饰附带的猪耳、皮肤及不透明镜片，没有重生成猪咪主体、眼睛或嘴。原图字节不再路由到运行装扮，旧来源和完整提示词保留为生成记录的 `previous_revision`。
- 新图原字节复制到原 `outfits.png` 路径，图集裁区只使用有意义的配饰连通区域；不由脚本重绘、拉伸或抹除原图。永久装扮 ID、价格、解锁、存档及十二项装扮动作不变。
- `pig_outfit_rig.json` 为十二种配饰和十二种身体提供独立的头部／眼部／颈部／身体附着、同比例尺寸、旋转、支点与遮挡规则。尺寸跟随每帧鼻宽，眼镜跟随双眼连线，不再使用一种固定尺寸套所有姿势。
- 趴卧、探头、低爬和护脸时隐藏被身体遮挡的颈部配饰，不改保存的穿戴选择；恢复无遮挡姿势时自动恢复。专用打工／主宰形态不叠加第二套装扮，四脚朝天不将披风贴到肚皮上。
- 静态缩略绘制和运行时身体共用配饰变换；配饰跟随呼吸、转向、姿势切换和场景缩放。小剧场创建角色时保留当前住客的实际穿戴，避免入场后突然脱掉配饰。

## 可复现覆盖

入口：`python3 tools/run_art_visual_audit.py --only outfits --output <证据目录>`。真实 OpenGL 渲染、不使用 Dummy 渲染器，隔离存档，音频保持静音。

- 12 身体 × 8 有效脸型 × 13 穿戴选择（12 件＋不穿）× 4 原稿帧 × 2 朝向：9,984 次实际静态绘制。
- 同一组合矩阵，四个呼吸相位、左右朝向：9,984 次实际运行时绘制。镜像、脸型和服装并非分别测后拼接推测。
- 12×12 姿势起止、8 脸型、13 穿戴、左右朝向和五个衔接采样：149,760 项联合过渡几何样本。检查等比、正交、完整画布、鼻嘴不被配饰盖住。
- 36 行为 × 48 永久表情 ID × 13 穿戴：22,464 项真实角色 API 映射；另检查五种性格的摸摸／戳戳表情。48 个收藏 ID 和旧瞳孔地震别名复用八种有效脸型，不虚构新的素材数量。
- 24 个小剧场 × 13 穿戴：312 个场景实际绘制，组成 13 页；此处每个事件取一个代表步骤，其他步骤的动作几何由身体／行为矩阵覆盖，不声称每条叙事时序都穷举。
- 配饰专项合计 999,627 项断言、205 张实际 PNG，通过；鼻部像素最大定位误差约 1.284 px，目录图集缓存仍不超过八张。
- Python 另检查每帧配饰的附着点确实接触主体原稿的 alpha 轮廓、两套眼镜镜片中心透明、缺失／非法规则被拒绝。没有用“文件能加载”代替视觉关联检查。

证据根目录：`build/validation/outfit-combinations-20261010/`。`serial-final/outfits/` 是配饰通过轮，`serial-final/menu.log` 是 637 项当前右键菜单通过轮；实际小屋／桌宠物品穿戴拼页、原稿全部视觉目录和连续动作证据分别见后续专项日志。物品拼页按不穿、目录顺序十二件装扮排列，五列三行，保留实际窗口画面的比例；这只是 QA 拼页，不进入游戏美术。

清场后串行复测 `clean-verified/interaction.log`：31,602 项通过，小屋和桌面两种旧偏好均检查 27 个物品动作，五档桌宠尺寸、接触点、配饰完整窗口和无重复奖励不变；81 页穿戴拼图共 1,053 次实际窗口组合采样，另有普通场景及 1280×720／16:10／超宽／80%／150% 布局截图。`clean-verified/art.log`：全部 226 视觉目录、原稿、脸型、装扮及姿势切换 2,130 项、37 PNG 通过；`render-verified/mouth.log` 独立嘴专项通过。`motion-verified/continuity.log`：480 帧／3,934 项通过，最大单步鼻部位移 1.765 px、渲染锚点误差 0.447 px。核心 7,080、拖动 85、Full／Demo 节奏、Demo profile 75、Python 169 和内容／视觉目录通过。

已直接查看十二种身体的标准组合整页（1,248 格）、镜像／第四帧／呼吸相位页及小剧场和实际物品穿戴拼页；其余图像由逐项像素与几何检查覆盖，不宣称人工逐像素审阅了所有 PNG。所有主体图、独立五官、家具、背景及 PigHub 来信原图的哈希都与无启动 Logo 预览相同；仅一个配饰 PNG 更新。

## 失败与验收边界

- 修前专项真实截图及十二项围巾宽度失败留在 `baseline/`。首次扩展矩阵误将运行时持有的身体纹理引用当作多绘制一层，导致 9,984 项层库存断言失败；纠正为检查引用库存及独立身体子节点实际绘制一层，没有修改生产绘制来迎合测试，失败留在 `joint/`。
- `final/` 的一次未完成渲染超时、`scene-final/` 的一次 Godot 4.6.3 导入线程崩溃不算通过。GUI 与其他引擎启动／应用切换分开，只有完整结束且无致命输出的日志算证据。
- 旧 `ui_copy_audit` 仍有三语相册布局 36 项失败和已删除侧栏的空引用，旧 `postcard_ui_audit` 仍调用已删除的来信气泡；未恢复侧栏／气泡，也未把这些旧脚本或全量 UI smoke 称为通过。当前菜单及视觉资源使用独立专项覆盖。
- 旧 `art_context_audit` 的家具比较仍按已废弃的四角插槽裁取背景指纹，19 项失败，不计为有效家具验收；32 件家具的真实单项绘制已在 `clean-verified/art/tokens-furniture-*.png` 查看，实际中央物品交互使用上述通过的联合专项。`clean-verified/source.json` 因该旧上下文失败保持整批 `complete=false`，其中只有 `interaction` 和 `art` 列为通过，不抹掉失败或伪称整批通过。
